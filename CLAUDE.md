## What this is

"Guionizador": a Next.js 16 (App Router, React 19, Tailwind 4) tool for writing e-learning course scripts. Domain language, UI text, identifiers, and commit messages are in Spanish; keep new code consistent with that.

## Commands

```bash
npm run dev          # dev server on http://localhost:3000
npm run build        # production build (also the main type check)
npm run lint         # eslint (flat config, next core-web-vitals + typescript)

npx prisma generate              # regenerate the client after editing prisma/schema.prisma
npx prisma db push               # sync schema to the DB (no prisma/migrations folder exists yet)
npx tsx prisma/seed.tsx          # seed the interaction/trigger catalog (idempotent upserts)
node test_openrouter.js          # smoke-test the OpenRouter key from .env.local
```

There is no test suite.

Env vars: `DATABASE_URL` (PostgreSQL) in `.env`/`.env.local`; `OPENROUTER_API_KEY` and `ANTHROPIC_API_KEY` in `.env.local`. Prisma is v6 (`@prisma/client` / `prisma-client-js` generator) even though the config file is named `prisma7.config.ts`. Don't apply Prisma 7 conventions (driver adapters, new generator) unless doing an explicit upgrade.

## Architecture

**Content hierarchy** (`prisma/schema.prisma`): `Curso → Leccion → Diapositiva → Capa → Item`. A Curso is shown as `linea_nivel_titulo_periodo`. A `Capa` (layer of a slide) is the main editing unit. It has an `estado` (`"borrador" | "aprobada"`), free-text script fields (explicacion, visual, audio, etc.), JSON `triggers` (`[{tipo, detalle}]`), and JSON `extra`.

**Data-driven interaction forms.** A Capa's `interaccion` is a string that matches `InteraccionCatalogo.nombre`. It is not a foreign key. Catalog rows (`tipo: "interaccion" | "trigger"`) carry `campos: RepeaterConfig[]`, a JSON schema that describes one or more repeaters: `kind`, `itemLabel`, `repeatable`, `fields: Campo[]`, and `audioCtx`. The editor renders forms from that schema:
- `components/CapaEditor.tsx` loads the capa via `/api/capas/[id]` and the whole catalog via `/api/interacciones`, finds the matching entry by name, and autosaves field changes with PATCH (debounced).
- `Repeater` → `ItemCard` → `DynField` render one repeater's items. `DynField` switches on `Campo.type` (`corto | largo | numero | imagen | lista`).
- Each `Item` stores its field values in `datos` (JSON keyed by `Campo.key`) and records which repeater it belongs to in `kind`.

To add a new interaction type, add it to the `interacciones` array in `prisma/seed.tsx` and re-seed. No UI code changes are needed. The shared TS shapes for these JSON columns live in `lib/types.ts`, and the seed file duplicates the `Campo` and `Repeater` types.

**Data access.** Server components query Prisma directly through the singleton in `lib/prisma.ts`, using `export const dynamic = "force-dynamic"`. Client components (`"use client"`, the `Crear*Form` components and the editor) call the REST handlers under `app/api/*`. Route handlers and pages use the async `params: Promise<{ id: string }>` signature, which Next.js 16 requires.

**Routing layout.** Route handlers live only under `app/api/<recurso>/`. Pages live only at `app/{cursos,lecciones,diapositivas,capas}/[id]/page.tsx`, and `/capas/[id]` renders `CapaEditor`. Don't put a `route.ts` next to a `page.tsx`. Mutable routes whitelist fields (`camposPermitidos`) instead of passing the request body to Prisma. After you delete or move routes, `npm run build` can fail on stale types in `.next/dev/types/validator.ts`. That folder is generated by `next dev`, so delete it.
